# TS43 Route Documentation

This document describes the TS43 Express router implemented in `routes/ts43.js`. It focuses on the flow, endpoints, and key helpers used to orchestrate a CIBA plus DCQL-based SIM verification.

## Location and Mounting

- **File**: `routes/ts43.js`
- **Mounted at**: `/ts43` (see `app.js`)

## Responsibilities

- Validate client configuration using `findClientByClientId`.
- Start a CIBA authentication request and retrieve an `auth_req_id`.
- Request a DCQL payload for a digital credential request.
- Accept a `vp_token`, exchange for an access token, and fetch user info.
- Store session data to drive the UI display.

## Endpoints

### POST `/ts43/auth`

Starts the TS43 flow by:

1. Posting to the CIBA auth endpoint to obtain `auth_req_id`.
2. Calling the DCQL endpoint using `auth_req_id` as a bearer token.
3. Returning the auth request ID, a generated nonce, and a digital request payload.

**Request body**:

- `client_id` (string, required)
- `login_hint` (string, optional)
- `carrier_hint` (string, optional)
- `operation` (string, optional)
- `scope` (string, optional)

**Response**:

- `auth_req_id` (string)
- `nonce` (string)
- `digital_request` (object)

#### CIBA Auth Call Details

The server calls the CIBA auth endpoint:

- **URL**: `${auth_server_url}/realms/${realm}/protocol/openid-connect/ext/ciba/auth`
- **Method**: `POST`
- **Content-Type**: `application/x-www-form-urlencoded`

**Form body** (sent by server):

- `client_id`
- `client_secret`
- `scope` (from request or client default)
- `login_hint` (optional)
- `carrier_hint` (optional)

**Minimal example**:

```bash
curl -X POST "$AUTH_SERVER_URL/realms/$REALM/protocol/openid-connect/ext/ciba/auth" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "client_id=$CLIENT_ID" \
  --data-urlencode "client_secret=$CLIENT_SECRET" \
  --data-urlencode "scope=openid" \
  --data-urlencode "login_hint=+1234567890" \
  --data-urlencode "carrier_hint=carrierX"
```

#### TS43 DCQL Call Details

After receiving `auth_req_id`, the server calls the DCQL endpoint:

- **URL**: `${auth_server_url}/realms/${realm}/protocol/openid-connect/ext/bc/ts43/dcql`
- **Method**: `POST`
- **Content-Type**: `application/json`
- **Authorization**: `Bearer ${auth_req_id}`

**JSON body**:

```json
{
  "operation": "GetPhoneNumber",
  "nonce": "<uuid>"
}
```

**Minimal example**:

```bash
curl -X POST "$AUTH_SERVER_URL/realms/$REALM/protocol/openid-connect/ext/bc/ts43/dcql" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $AUTH_REQ_ID" \
  -d '{"operation":"GetPhoneNumber","nonce":"<uuid>"}'
```

### POST `/ts43/token`

Completes the TS43 flow by:

1. Posting `vp_token` to the callback endpoint.
2. Exchanging `auth_req_id` for an access token at the token endpoint.
3. Fetching user info and storing it in the session.

**Request body**:

- `vp_token` (string, required)
- `auth_req_id` (string, required)
- `client_id` (string, required)
- `nonce` (string, required)

**Response**:

- On success: user info JSON
- On error: error JSON (also stored in session for UI visibility)

## Key Helpers

- `resolveOperation(operation, loginHint)` picks the TS43 operation based on the request input.
- `buildCibaAuthFormData(...)` prepares the form body for the CIBA auth request.
- `buildDigitalRequest(nonce, dcqlData)` builds the OpenID4VP DC API request.
- `callCallbackEndpoint(callbackUrl, vpToken, authReqId)` posts the VP token to the TS43 callback.
- `buildSessionUserData(userInfo, clientId, nonce)` normalizes session data for UI rendering.

## Code Snippet

The snippet below shows how the router constructs the DC API request and returns it alongside the `auth_req_id`:

```javascript
const dcqlResponse = await axios.post(dcqlUrl, dcqlPayload, {
  headers: {
    Authorization: `Bearer ${authReqId}`,
    ...getJsonConfig().headers,
  },
});

res.json({
  auth_req_id: authReqId,
  nonce: ts43_nonce,
  digital_request: buildDigitalRequest(ts43_nonce, dcqlResponse.data),
});
```
